# 踩坑记录（LESSONS）

> 这份文档比代码更值钱：**每一条都是真实事故**，代价是用户的一次投诉或一整晚的排查。
> 改代码前扫一遍，能省你几天。

格式：现象 → 根因 → 修法 → 教训。

---

## 1. 模型说“好”没有约束力

**现象**：朋友说「以后九点多之后再给我发消息」，她回「好，这下我记全了」，然后照旧早上发。

**根因**：约束只活在对话里，**没有任何一处代码去读它**。

**修法**：自然语言 → 结构化规则（`whale/behavior/rules.py`）→ 主动发送前查 `allows_proactive()`。
模型只负责抽取 JSON，时间/星期/间隔全部由代码校验。

**教训**：凡是“他要求了什么，我要做到”的功能，都要有**代码闸门**，不能只在提示词里写一句。

---

## 2. 时间不能交给模型算

**现象**：23:25 说「11点30叫我一下」，她答「好，十一点半我叫你」，到点没响。

**根因**：日志写着 `排了定时：11:30` —— 按字面排成了**今天上午 11:30**，
已经过了 → 兜底 `+86400` → 变成**明天上午 11:30**。

**修法**：`remind.nearest_at("11:30")` 在「今天 11:30 / 今天 23:30 / 明天 11:30 / 明天 23:30」
里取最近的未来点；模型给的 `today/tomorrow` 完全不信。

**派生问题**（同一类，后来又踩两次）：
- 23:44 说「晚上 11 点半」→“晚上”已消除歧义 → 不反问 → 顺延到明天 23:30，
  等于排到 23 小时后。→ 加 `past_question()`：「今天 23:30 已经过去 14 分钟，你是说明天吗」。
- `nearest_at` 对 `hh>12` 也加 +12h 候选 → 23:44 说「23:30」被算成明天 11:30。
  → 只有 `hh<=12` 才加。

**教训**：把“时间说法”落成具体时刻，**必须由代码按 now 算**；模型只给 `HH:MM`。

---

## 3. 隐私：共用一段代码 = 迟早泄露

**现象**：朋友问「不记得了吗」，她回了一大段「记忆里存着 138 条对话……旧对话摘要：对方自称千鹤……」，
末尾还有「· 爸爸：(发来一个表情包)」——**把主人的存在漏给了朋友**。

**根因两层**：
1. `[[查:记忆]]` 这个自查分支**没判身份**，朋友也能触发；
2. `_introspect()` 里“谁”写死成 `"爸爸"`，于是朋友的历史里每句话都被标成「爸爸：」。

**修法（四层，缺一层都会漏）**：
- 入口：`found = ... if is_owner(cid) else None`；
- 生成：朋友路径不塞主人的事实/梦；
- 发送前：`_sanitize_for_friend()` 再过滤一遍；
- 数据：把已污染的 10 条记忆删掉（留备份），并给 `strip_markers()` 补上遗漏的标记。

**教训**：凡是“同一段代码服务两种身份”，输出里的人称、称呼、隐私字段**必须按身份分支**。

## 4. 缓存会绕过所有新逻辑

**现象**：修好选歌逻辑后重启，点《蔷薇》收到的还是那段游戏解说。

**根因**：错的那首歌**已经被存进曲库**了。点歌**先查曲库**，命中就秒发第一段——
新代码根本没机会跑；后面几段才走新逻辑，于是“卡住”。

**修法**：
- `songlib.find()` 读出时校验（不像歌的条目当不存在）；
- `add_segment()` 写入时拒绝脏条目；
- 清库：删掉错的条目和**坏音频**（用 −6 半音做出来的那段，也得删，否则还是怪声）。

**教训**：凡是“先查缓存命中就用”的路径，必须和主路径**用同一个校验函数**，
否则改多少遍都没用。

## 5. “生成成功” ≠ “用户收到”

**现象**：用户问「她怎么还没发给我唱歌」。歌其实做好了，938 KB 躺在服务器上。

**根因**：补发函数第一行 `sing.pretty_title(...)` —— **`sing` 没在 whale/bot.py 里 import**，
`NameError` 直接把整个补发函数干掉，发音频那行一行都没执行。

**修法**：
- 补 `import sing`；
- 取标题加 try/except：**取不到名字也得把歌发出去**；
- 自测加一项：用 AST 扫 whale/bot.py 里所有 `模块.属性` 访问，本地模块没 import 就报错（并做过反向验证）。

**教训**：收尾那一步要能独立失败、失败要吼出来。只写一行 WARNING 等于没写。

## 6. 她自己会编“我做过什么”

**现象**：一个朋友点了歌（好感度 27 < 40，门禁拦了，一句没唱），
92 分钟后她说「刚唱的这首怎么样呀？要不要换一首？」——**从头到尾没唱过**。

**根因**：她没有“我到底做过什么”的硬依据，只能靠对话历史猜；
历史里那条「（我刚发了一段语音…）」是 90 分钟前的，读起来像“刚刚”。

**修法：行动台账**
- `state.json` 的 `actions` 记录真实发过的动作（sing/video/sticker + 时间戳）；
- 提示词里给她台账（有就列，没有就明说“你今天还没唱过”）；
- **发送前核对**：回复里出现「刚唱 / 我唱了 / 刚才那首」而台账 15 分钟内没有 sing → 删掉那句；
  整条都是这种话就换成「我这会儿还唱不了呀」（按好感度门禁区分文案）。

**教训**：**“她说过什么”不是证据，“系统记了什么”才是。**

## 7. 过滤规则宁可少排除，不要多排除

**现象**：用户给了 B 站链接说「有完整的整首歌啊」。查了一下，完整版就在结果里，**被我自己的规则判死**。

**根因三连环**：
1. 规则「歌名 ≤2 字必须有 MV/歌曲/唱 这类词」太粗——完整版标题里一个都没有；
2. “独立出现”的判断跑在 `_norm()` 之后的文本上（书名号和空格都被删了），**所有歌都判不独立**；
3. 时长打平：1:15 和 3:57 同分，稳定排序让先出现的短片赢了。

**修法**：改判「歌名独立出现」（前后不是中文/字母数字）、在**原始标题**上判、
时长明确偏好完整版（2.5–6 分钟 +4）。

**教训**：评判一条过滤规则的标准是「**他要的那首还在不在**」，不是“我挡掉了多少噪音”。

## 8. 一个 import 和一次“看起来没问题”的自测

**现象**：本地测试全绿，线上功能不工作。

**根因**：本地测试是直接 `import sing` 调的，而 whale/bot.py 顶部没有 `import sing`。
测的是“模块能不能用”，不是“bot 能不能用”。

**修法**：selfcheck 加“whale/bot.py 用到的本地模块都导入了吗”（AST 静态检查）。

**教训**：自测要测**真实入口**，不是测“我改的那个函数”。

---

## 9. `.bat` 里不能出现中文

**现象**：双击桌面快捷方式，窗口一闪就没。

**根因**：cmd 按 GBK 解析 `.bat`，UTF-8 的中文变成乱码路径 → 找不到文件 → 直接退出。

**修法**：`.bat` 只做三行启动器（`cd /d "%~dp0"` + `python xxx.py` + `pause`），
**逻辑全部搬到 Python**（Python 自己控制编码）。全项目 `.bat` 的非 ASCII 字节数必须是 0。

## 10. 群里/朋友侧的功能要先想清楚“谁在看”

**现象**：她跟一个开了「自动回复」的号互相客套了 83 条。

**根因**：对方号上挂着自动回复机器人，她回一句、对面回一句，无限循环。

**修法**：文本识别 `[自动回复]` / `【自动回复】` → **整条不理**（不调模型，省 token）。
注意：**对方开了自动回复 ≠ 对方是机器人**，所以只处理“这一条消息”，
不要顺手把这个人的长期状态改掉（用户明确纠正过这一点）。

---

## 11. 测试里最容易骗自己的三件事

1. **假模型返回的格式不对**：规则抽取测不出来，是因为假模型返回了纯文本，`json.loads` 失败被 `except` 吞了。
   → 假模型的返回值必须按调用意图构造。
2. **等的时间不够**：定时循环 10 秒一次，测“2 秒后触发”必然失败。
   → 至少等一个完整周期。
3. **触发了频率限制**：同一个号连发 4 条消息后两条会被限流（保护 QQ 号），
   不是指令坏了。→ 测指令直接调 `handle_command()`。

## 12. 关于“她不够聪明”的通解

用户提过多次「感觉她不够智能，只能口头答应」。真正的解法不是换更大的模型，而是：

**把“理解”交给模型，把“执行”交给代码。**

- 模型：把自然语言变成结构化字段（时间、话题、动作、情绪）
- 代码：校验字段、判歧义、算时间、执行拦截、事后核对

这条原则覆盖了本项目 80% 的“她怎么又犯傻”问题。

## 13. 两次关于“身份预设”的教训（同一件事栽两遍）

**第一版**：把恋人默认写成“男朋友/他” →
用户：「万一是女同性恋呢」。

**第二版**：只认「恋人/朋友」两种关系 →
用户：「要不让我自己设定关系吧，比如 `/设关系 qq号 女朋友/男朋友`」。

**定稿**：关系词完全自由（女朋友/男朋友/妹妹/老大…），按类别决定语气，
性别取显式或从词里推，**推不出就全程用“对方”，并禁止她替对方定性别**。

**教训**：涉及“关系 / 性别 / 身份”的字段，**不要替用户预设**。
你以为的默认值，对别人就是错的。
